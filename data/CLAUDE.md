# data/ — 毎年ここを差し替える

このフォルダは**税率表・料率・参照リンクの置き場**。
コード（`src/`）にこれらの数値やURLを埋めない、というのが本プロジェクトの設計原則3。

**改正対応の作業は、原則としてこのフォルダのファイルを直すだけで完結する。**
ここを直すのにプログラムの知識は要らない。税務がわかる職員なら誰でもできる状態を保つ（属人化対策）。

---

## 守ること

### 1. 適用年度を必ず持たせる

すべてのデータに適用年度（または適用期間）のフィールドを持たせ、**画面にも表示する**。

理由：危険なのはリンク切れではなく、**古い内容が正常に表示されること**。
国税庁の源泉徴収税額表や協会けんぽの保険料額表は年度ごとに別ページとして新設されるため、
去年のURLを貼ったままだとリンクは生きていて、正しく表示され、中身だけが古い。誰も気づかない。
年度が画面に見えていれば人が気づける。これが更新漏れに対する最後の防波堤。

### 2. 改正は上書きせず、版を足す

過年度の試算（修正申告・遺産分割のやり直し）を関与先で出すため、**旧年度のデータを消さない**。
「令和7年分まではA、令和8年分からはB」を両方保持する。

### 3. 出典を書く

各データファイルに、根拠となる法令・告示・公表資料の名称とURLを記載する。
**記憶で数値を書かない。** 条文・告示の原文を確認してから入れる。

★**「現行施行版」だけを見ない。** 成立済みで未施行の改正が、その年分にはもう適用されることがある
（所得税の年分改正は、その年の12月1日に施行して当年分から適用するのが通例）。
e-Gov のリビジョン一覧（`/api/2/law_revisions/<law_id>`）で施行日が先のものを必ず確認し、
適用年分は改正法の附則（経過措置）で読む。これを飛ばして1度外している → 判断ログ D-28。

### 4. このフォルダを直すだけなら、プログラム側の作業は要らない

`data/*.json` はアプリが**毎回取りに行く**設定になっている（判断ログ D-16）。
このフォルダのファイルを差し替えて公開すれば、**その日のうちに全職員の端末へ反映される**。
`sw.js` の `CACHE_VERSION` を上げる必要はない（それが必要なのは `src/` のロジックを変えたときだけ）。

### 5. リンク集には最終更新日を持たせる

リンク集のデータには「このリンク集をいつ確認したか」の日付を持たせ、画面下に表示する。
半年前の日付が出ていれば、職員が疑って原典を確認できる。

### 例外：自動生成しているファイルは手で編集しない

次の3つは**条文から機械的に生成**している。人が転記すると必ずどこかを間違え、
しかも画面には**もっともらしい結果が出てしまう**ため（判断ログ D-18・D-20・D-22）。

改正があったら、編集ではなく再生成する：

```
node tools/fetch_shokyakuritsu.mjs      # shokyakuritsu.json（耐用年数省令の別表第八〜第十／約900個の数値）
node tools/fetch_inshizei.mjs           # inshizei_hyo.json（印紙税法別表第一の全20号／措置法91条）
node tools/fetch_toroku_menkyozei.mjs   # toroku_menkyozei_hyo.json（登録免許税法別表第一の第1号・第24号／措置法72条・72条の2・73条・75条）
npm test
```

### 所得税の別表第五は「生成」ではなく「照合」する

`shotokuzei.json` は別表第五の表そのものを持たず、しきい値と刻みから再現している。
数値を足したり刻みを変えたりしたら、必ず原文の全行と突き合わせる。

```
node tools/verify_besshi5.mjs           # 収録している全年分
node tools/verify_besshi5.mjs 2026      # その年分だけ
```

不規則な区分が実際に現れる（令和8年分は刻みの開始が2,026,000で、最初の1区分だけ幅2,000円）。
式を組んだだけでは検算にならない → 判断ログ D-28。

**軽減措置が延長されたときは、再生成だけでは済まない**（テストの日付の書き換えが要る＝開発者の作業）。
→ `docs/改正対応手順.md` の「`data/` を直すだけでは済まないもの」

### 所得税エンジンの3ファイルは対で直す

`shotokuzei.json` の `人的控除`／`juminzei.json` の `所得控除`／同 `調整控除.人的控除差額表` は、
**同じ人的控除に同じキー名を使う約束**になっている（テストが一致を検査する）。
控除の項目が増減したときは3箇所を対で直すこと。詳しくは `docs/改正対応手順.md` と判断ログ D-27。

★**住民税の版は「所得の年分」で持つ。** 改正の告知は「令和○年度分以後」と書かれるので、
**年度 − 1 ＝ 年分**に読み替えてから版を足す。

## 置かないもの

- **数値表をアプリに自前で持つのは Rule of Three 後**。まずはリンクで運用し、「毎回同じページばかり開いている」ものが3つ以上見えてから、その数個だけ取り込む。先回りして料率表を抱えると、スコープ外にした給与計算の保守が裏口から戻る
- 源泉徴収税額表そのもの（巨大かつ年に複数回更新。リンクで足りる）
- 路線価（毎年の全国データ調達が最も重い。第1版では持たない）
