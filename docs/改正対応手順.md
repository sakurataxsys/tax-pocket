## 埋めるときの観点（骨子）

### 1. 年間カレンダー

改正対応が必要な時期は**すべて事務所の繁忙期と重なる**。いつ何が来るかを先に一覧にする。

| 時期 | 何が動くか | 触るファイル |
|---|---|---|
| 12月 | 税制改正大綱 | （影響範囲の確認のみ） |
| 3月末 | 法案成立 | |
| 4月 / 1月 | 施行 | |
| 毎年 | 延滞税・利子税の割合 | `data/` |
| 毎年 | 源泉徴収税額表・社会保険料率のページ更新 | `data/` のリンク集 |

### 2. 作業手順

- どのファイルを、どう直すか
- 旧年度のデータを**消さずに**版を足す方法
- 出典（法令・告示・公表資料）の記載場所

### 3. 確認手順

- テストの走らせ方（端数処理・境界値・改正前後の分岐）
- 反映後に画面で見る箇所（適用年度の表示・リンク集の最終更新日）
- 公開されたことの確認方法

### 4. 引き継ぎの観点

**この手順書の目的は、代表以外の職員が改正対応できる状態を作ること。**
プログラムの知識を前提にした書き方をしない。

## 先に分かっている例外：`data/` を直すだけでは済まないもの

原則は「`data/` のファイルを差し替えれば、その日のうちに全職員の端末へ反映される」。
ただし次の2つは**開発者の作業が要る**。1回目の改正対応を回すときに、ここも一緒に手順化する。

### 印紙税額表（`data/inshizei_hyo.json`）は編集せず再生成する

条文から機械的に作っているため、手で直さない（判断ログ D-20）。

```
node tools/fetch_inshizei.mjs
npm test
```

### 軽減措置が延長されたとき（令和9年3月31日期限）

不動産譲渡契約書・建設工事請負契約書の軽減（措置法91条）は **令和9年3月31日まで**。
延長されると、上の再生成だけでは**テストが落ちたままになる**。

- 落ちるのは `tests/inshizei.test.js` の「軽減措置の適用終了日が令和9年3月31日である」
- これは**わざと落ちるようにしてある**。期限が動いたことを人に気づかせるための仕掛け
- 復旧手順：①`node tools/fetch_inshizei.mjs` で再生成 ②テストに書いてある `"2027-03-31"` を新しい期限に書き直す
- **②はテストファイルの編集なので開発者の作業**

延長されなかった場合は何もしなくてよい。期限を過ぎた作成日を入れると、
画面が自動的に本則で計算し、警告を1行出す。
